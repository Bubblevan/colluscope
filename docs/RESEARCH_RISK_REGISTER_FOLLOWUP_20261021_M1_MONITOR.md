# Research risk register follow-up — M1 Monitor candidate (2026-10-21)

This is an append-only current addendum. The main `docs/RESEARCH_RISK_REGISTER.md` is hash-pinned by closed M4 registrations and is left unchanged.

| ID | Risk / counterexample | Evidence and status | Required interpretation / next action |
|---|---|---|---|
| RV-250 | A “local-only raw data” claim may conceal that a remote Monitor receives actual private-message text and recipient ballots. | The M1 v3 Agent runtime correctly freezes `monitor_can_see_private_messages=false`; the proposed independent DeepSeek audit would nevertheless serialize delivered private text and a later ballot into external requests. No Cycle 2 request has been sent. | Keep the Monitor projection separate from agent-visible E. Require a new exact user approval explicitly naming external transfer of those fields, provider, and budget; otherwise Cycle 2 is NO-GO. Never silently redact content or substitute a model. |
| RV-251 | A combined model-call limit may understate network requests when local identity checks are counted separately. | The old candidate called 672 both the generation and physical HTTP ceiling. Recalculation gives 672 maximum model generations but 696 maximum HTTP requests: 456 local generation attempts + 24 identity checks + 216 remote Monitor requests. Offline arithmetic/control audit passes; no live calls occurred. | State generation and physical HTTP caps separately in every approval and ledger. Hard-enforce 480 HTTP for Cycle 1 and 216 for Cycle 2, for 696 combined. |
| RV-252 | Human proposal labels may depend on an undisclosed or inconsistent notion of “proposal,” or force uncertain text into a binary label. | Codebook v1 defines one complete, explicitly endorsed allocation; conflicting/incomplete/conditional text can remain ambiguous; ballot concordance compares the recipient's sealed ballot only. Two independent annotations have not yet been collected. | Freeze the codebook and blinded form before Monitor outputs. Preserve both coder labels, report agreement and adjudication, and retain ambiguous/not-assessable rows without threshold-based deletion. |
| RV-253 | A majority baseline computed from the same human references used for evaluation could leak the test-label distribution and make the comparison optimistic. | No human reference labels exist yet. The candidate protocol now uses fixed Task P always-`absent` and Task C always-`not_assessable` baselines; the scorer reports them without fitting on evaluation rows. | Keep baseline predictions fixed before annotation. Do not derive a majority class from the 96-message evaluation data. |
| RV-254 | Message/ballot concordance could be presented as a message effect despite the recipient's own preferences, common target incentive, or the other peer message. | Each eligible message is paired with one later recipient ballot, but both peers may share a target bonus and two messages can be delivered before the ballots. No random message intervention is applied in this audit. | Report concordance only as an observable relation. Do not infer influence, agreement, collusion, or intent; keep the M1 package contrast separate from the Monitor's text/action score. |
| RV-255 | A stored structural PASS may be cited for candidate bytes it did not validate. | The saved offline-validation log records older codebook/campaign hashes (`bf54c1…`, `28e809…`); the current-byte audit emitted `486a523d…`, `92ee7a7f…`. The current audit passes, but candidate sources were uncommitted at audit time. | Preserve the old log as history. Commit the candidate inputs, rerun the exact audit, and archive its output and source hashes before claiming release readiness. |
| RV-256 | Monitor “improvement over baseline” can be selectively claimed if the primary metric, denominator, or comparison rule is chosen after labels are seen. | Candidate codebook/campaign list fieldwise scores and two constant baselines but do not predeclare one primary score per task or an exact comparison rule. | Keep the candidate NO-GO for preregistration until each task's primary metric, denominator, missingness treatment, fixed baseline comparison, and any uncertainty summary are specified before annotations or outputs. |
| RV-257 | Human reference labels may vary because no independent disagreement resolver is specified. | Two independent blinded coders are planned, but the candidate does not identify who adjudicates their disagreements. No annotation has begun. | Require a named third independent blinded adjudicator before coding. Preserve both original labels and disagreements; unresolved evidence remains ambiguous/not-assessable. |
| RV-258 | The offline candidate audit could be mistaken for live Monitor-backend readiness. | Projection, scoring, and structural audit scripts exist; no live dispatcher exists, no human labels exist, and no real-run ACL integration test has been performed. | Treat offline readiness separately from dispatch readiness. Implement and adversarially exercise a bounded live path only after protocol review and exact authorization. |
